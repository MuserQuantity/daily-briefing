# 任务：每日生成并发布一期 AI 日报

每天执行一次。产出一期日报，通过 HTTP 接口发布到 https://ai-daily.muserquantity.cn
核心要求：内容不得与已发布的任何一期重复。

## 一、先拉取已发布内容（这是去重的依据，不能跳过）

GET https://ai-daily.muserquantity.cn/api/daily
Header: Authorization: Bearer <DAILY_API_TOKEN>

返回：
  {"ok":true,"today":"2026-07-30","count":N,
   "items":[{"date","title","issue","summary","tags","highlights"}, ...]}
items 按日期倒序，最新在前。

从返回里取三样东西：
1. today —— 本期日期，直接用这个值，不要用你自己的时钟（站点以 UTC+8 计日）
2. items 里最大的 issue + 1 —— 本期期号；若都没有 issue，从 1 开始
3. 全部 items 的 title / summary / highlights —— 汇总成「已覆盖清单」

如果 items 里已经存在 today 这一天，说明今天已经发过了：停止并报告，
不要自动覆盖（除非我另行指示）。

需要更细的历史内容时，直接抓页面正文：
  https://ai-daily.muserquantity.cn/d/<日期>
建议至少细读最近 7 期。

## 二、去重规则（本任务的核心）

对每一条备选内容，跟「已覆盖清单」逐条比对，按下面判定：

【排除】同一事件、同一发布、同一组数字已经写过 —— 哪怕换个说法也不行
【排除】只是把旧内容重新组织、换标题、换角度复述
【排除】拿不准是否写过 —— 宁可少写一条，也不要冒险重复

【允许】同一条线索有实质性新进展。但必须满足两点：
  a. 新进展本身有信息量（新数据、新版本、结果落地、态度反转等），
     不能是「XX 事件仍在发酵」这种没有增量的话
  b. 正文里要显式交代增量，例如「7 月 24 日那期提到 A 厂商降价 48%，
     今天 B、C 两家跟进，且缓存命中价降到原价一成」
     —— 让读者知道新在哪，而不是重新讲一遍旧事

注意：tags 是分类标签，重复使用是正常的，不受本节约束。
本节只约束「内容/信息」不重复。

## 三、选题与真实性要求

- 时间窗口：以最近 24 小时内的进展为主，最多不超过 48 小时
- 每期 3–5 个 ## 章节，每章 1–3 条消息
- 宁缺毋滥：当天确实没有足够有价值的新进展时，就发一期短的，
  不要用凑数内容或翻炒旧闻填满

真实性（最重要，违反此条这期就是废的）：
- 每条消息都必须有真实、可访问的来源链接，链接你要实际打开确认过
- 不要编造数字。引用数据时注明出处，例如「据 XX 官方博客」
- 传闻、爆料、未证实的消息，必须明确标注为传闻，不能写成既成事实
- 拿不准的内容直接不写

## 四、正文里不许出现的东西

content 是给读者看的成品，不是工作记录。以下内容一律**只写进第七节的报告**，
绝对不要写进 content，也不要作为章节出现在正文里：

- 去重说明、补录说明、「本期未收录 XX 因为与某期重复」
- 执行过程、检索过程、数据来源筛选过程
- 「本期由 AI 生成」之类的免责声明或自述
- 任何形式的 TODO、待确认、占位符

正文只包含当天的新闻内容本身。

## 五、结构与字段规范

### 5.1 章节结构

- 不要写 `# 一级标题`。主标题通过 title 字段提供，正文从 `##` 开始
- 用 3–5 个 `##` 按**主题**分章，例如：模型与产品 / 工程实践 /
  政策与监管 / 资本与人事。**不要**用「速览」「要点」这种把所有条目
  堆在一章里的写法
- 每章下用 `###` 写具体条目，一章 1–3 条
- 右侧目录由 ##/### 自动生成，所以章节标题要能独立看懂

### 5.2 highlights 与正文不要重复

highlights 是卡片式的「一句话摘要」，正文是展开叙述，两者会同时显示在
同一个页面上。因此：

- highlights 的文字**不要和正文的章节标题一模一样**
- highlights 写「结论/影响」，正文标题写「事件本身」
  例：highlights 写「三家厂商同周降价，长上下文均价降近半」，
      正文标题写「### 长上下文定价集体下调」
- 3–5 条，覆盖当天最重要的几件事即可，不要把每条新闻都列进去

### 5.3 summary

- 1–2 句，**80 字以内**
- 必须是**语义完整的句子**，以句号结尾
- 严禁在中途截断（不能出现「……推出新一批国家科技挑战（Nat」这种断尾）
- 写本期主线，不要罗列条目

### 5.4 来源

每期末尾必须附 sources 块：

```sources
来源标题一 | https://example.com/a | 官方
来源标题二 | https://example.com/b
```

- 每行「标题 | 链接 | 备注」，备注可省略
- 分隔符是半角竖线 |，全角 ｜ 无效
- 单元格内不能出现 |（无转义机制），标题里有就换成 / 或 ，

### 5.5 可选排版块

内容合适才用，不要为用而用：
- ```stat      指标卡：标签 | 数值 | 变化（变化以 - 开头显示红色下降箭头）
- ```quote     大字引言：末行以「— 」开头视为出处
- ```kv        参数表：键 | 值
- ```timeline  时间线：时刻 | 事件 | 说明
- ```compare   对比表：首行表头，单元格 yes/no/na 渲染成图标
- 提示块：> [!TIP] 标题，类型有 NOTE/TIP/IMPORTANT/WARNING/CAUTION

这些块内按纯文本渲染，**粗体**、[链接]() 不生效（提示块除外），
同样受「半角 | 分隔、单元格内不含 |」约束。

## 六、发布

POST https://ai-daily.muserquantity.cn/api/daily
Header:
  Authorization: Bearer <DAILY_API_TOKEN>
  Content-Type: application/json

Body：
| 字段 | 类型 | 说明 |
| --- | --- | --- |
| date | string | 用第一步拿到的 today |
| title | string | 主标题，**22 字以内**，概括当天主线，不要写成「X月X日AI日报」 |
| issue | number | 第一步算出的期号，必须是数字 |
| editor | string | 固定填 "编辑部" |
| summary | string | 见 5.3 |
| tags | string[] | 3–5 个，每个 2–6 字 |
| highlights | string[] | 见 5.2。纯文本，不带 Markdown 语法 |
| content | string | 正文，见第四、五节 |

标题 22 字是版式约束：正文列宽 48rem，标题字号 2.2rem，超过约 22 个汉字
就会折行，容易折出难看的断点。

frontmatter 由服务端自动拼装，不用管 YAML 转义。

成功返回 {"ok":true,"action":"created","date":"...","file":"...","bytes":N}

失败处理：
| 状态码 | 处理 |
| --- | --- |
| 400 | 内容没落盘，看 message 修正后重试（最多 3 次） |
| 401 | 停止并报告，不要重试 |
| 413 | 正文超 1 MB，精简后重试 |
| 503 | 站点未开启接口，停止并报告 |
| 5xx / 超时 | 间隔 30 秒重试，最多 3 次 |

同一天重复发布会覆盖，幂等，所以重试是安全的。

发布成功后打开 https://ai-daily.muserquantity.cn/d/<date> 自查：
- 标题是否完整显示、没有奇怪断行
- 导语是否完整、没有截断
- 右侧目录的章节是否清晰，且没有和要点速览卡片重复
- 正文里没有出现任何过程性说明

## 七、报告（只给我看，不写进正文）

- 本期日期、期号、标题、发布结果
- 本期覆盖的话题列表
- 因判定为重复而排除的话题，以及它跟哪一期重复
- 作为「后续进展」写入的话题，以及相比哪一期新增了什么
- 失败或异常

## 今日概览

推理价格战在本周进入新阶段。与过去以「短上下文降价换量」为主的策略不同，这一轮下调集中在 **长上下文与缓存命中场景**，直接影响的是文档处理、代码库理解和长会话记忆类产品的成本结构。

```stat
长上下文均价降幅 | 48% | -48%
端侧模型月活设备 | 9.1 亿 | +23%
智能体任务平均步数 | 34 | +11%
```

对应用层来说，最直接的变化是「上下文预算」不再是首要约束。此前普遍采用的检索压缩、摘要链路，有一部分可以退回到直接投喂原文。

> [!TIP] 落地建议
> 如果你的产品此前为了省钱做了激进的上下文裁剪，现在值得重新做一次 A/B：
> 把裁剪比例放宽 2 倍，观察答案质量与成本的实际交换比。

## 模型与产品

### 端侧模型越过临界点

端侧部署量首次反超云端，背后有三个推动因素：

1. **量化方案成熟** — 4-bit 权重加动态激活量化的组合，在多数消费级芯片上已能稳定跑到可用延迟。
2. **系统级入口开放** — 输入法、相册、浏览器摘要等高频入口默认接入本地模型。
3. **隐私合规压力** — 涉及通讯录、相册、位置的功能，本地推理是成本最低的合规路径。

```kv
典型参数量 | 2B – 8B
首 token 延迟 | 120 – 400 ms
峰值内存占用 | 1.2 – 3.6 GB
常见落地场景 | 摘要、改写、意图识别、本地检索
```

值得注意的是，端侧并没有取代云端，而是把 **调用分层** 变成了默认架构：本地负责高频短任务，云端负责低频重任务。

```compare
能力 | 端侧 2B | 端侧 8B | 云端旗舰
离线可用 | yes | yes | no
长上下文（128K+） | no | no | yes
函数调用 | yes | yes | yes
复杂多步推理 | no | na | yes
单次成本 | 近乎为零 | 近乎为零 | 按 token 计费
```

### 多模态智能体评测出现新共识

新发布的评测集把重点从「单轮能力」转向「长任务稳定性」，评分维度包括：

| 维度 | 权重 | 说明 |
| --- | --- | --- |
| 任务完成率 | 40% | 端到端是否达成用户目标 |
| 工具调用正确率 | 25% | 参数构造与错误恢复 |
| 步数效率 | 20% | 完成同一任务所需步数 |
| 成本 | 15% | 折算为统一计价单位 |

```quote
我们不再关心模型能不能答对一道题，而是关心它连续工作四十步之后还剩多少可靠性。
— MM-Agent 评测集作者访谈
```

> [!WARNING] 评测的局限
> 该评测集的工具环境是模拟的，与真实 API 的超时、限流、脏数据差异很大。
> 线上表现通常比评测分数低 15% – 30%，不要直接把榜单成绩当作选型依据。

## 工程实践

本周社区讨论最多的是「缓存友好的 prompt 结构」。核心结论很朴素：把稳定内容放前面，变化内容放后面。

```ts
// 稳定前缀（可缓存）→ 变化后缀（不可缓存）
const messages = [
  { role: 'system', content: SYSTEM_PROMPT },   // 几乎不变
  { role: 'user', content: KNOWLEDGE_BLOCK },   // 按天更新
  { role: 'user', content: userQuestion },      // 每次都变
]
```

在缓存命中率从 30% 提升到 80% 的实测案例中，单次请求成本下降约 55%，而首 token 延迟下降约 40%。

> [!NOTE] 一句话总结
> 这一轮降价真正奖励的是「结构清晰、前缀稳定」的工程实现，而不是单纯的用量规模。

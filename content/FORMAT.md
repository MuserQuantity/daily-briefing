# AI 日报 Markdown 格式规范

供自动任务生成日报文件使用。**本文件不会被网站渲染**（渲染目录只扫描 `content/daily/`）。

---

## 1. 文件位置与命名

```
content/daily/YYYY-MM-DD.md
```

- 目录固定为 `content/daily/`，扩展名 `.md` 或 `.mdx`。
- 文件名的日期即该期日期，**以 UTC+8 为准**。例：`content/daily/2026-07-30.md`。
- 一天一个文件。同名文件会被覆盖。
- 站点排序、归档分组、上下期导航全部由文件名日期推导，无需额外索引文件。

网站行为：首页取当前 UTC+8 日期对应的文件；若不存在，则回退显示最新一期，并在顶部加一条「今日尚未发布」提示。所以自动任务**只需按时写文件**，不需要改任何代码。

---

## 2. Frontmatter（YAML）

必须位于文件最开头，用 `---` 包裹。

```yaml
---
title: 推理成本再降一半，端侧模型开始抢占入口
date: '2026-07-30'
issue: 214
editor: 编辑部
summary: 主流推理服务价格集体下调，端侧小模型部署量首次超过云端调用量。
tags:
  - 模型发布
  - 推理成本
highlights:
  - 三家主流厂商在同一周内下调长上下文定价，平均降幅 48%
  - 端侧模型月活设备突破 9 亿台
---
```

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `title` | string | 建议 | 主标题。缺省时回退为 `AI 日报 · YYYY-MM-DD`。控制在 30 字内，避免折行过多。 |
| `date` | string | 否 | `YYYY-MM-DD`。**必须加引号**，否则 YAML 会解析成 Date 对象。缺省或格式非法时用文件名日期。 |
| `issue` | number | 否 | 期号，显示为「第 214 期」。必须是数字，不要写成 `'214'`。 |
| `editor` | string | 否 | 署名。 |
| `summary` | string | 否 | 导语，1–2 句。同时用作页面 `<meta description>`。 |
| `tags` | string[] | 否 | 标签。建议 3–5 个，每个 2–6 字。也接受单个字符串。 |
| `highlights` | string[] | 否 | 「要点速览」条目。建议 3–5 条，每条一句话，不要带 Markdown 语法（按纯文本渲染）。 |

> 阅读时长由正文字数自动计算，不需要提供。

## 3. 正文：标准 Markdown

支持 GFM 全集（表格、删除线、任务列表、自动链接）。渲染约定：

| 语法 | 渲染结果 |
| --- | --- |
| `## 二级标题` | 章节标题，**自动进入右侧「本页目录」**，带锚点 |
| `### 三级标题` | 子标题，也进入目录（缩进一级） |
| `#### 四级标题` | 小标题，不进目录 |
| `# 一级标题` | 不要用。主标题已由 frontmatter 的 `title` 提供 |
| `---` | 分隔线 |
| `**粗体**` / `` `代码` `` / `[链接](url)` | 常规样式，外链自动 `target="_blank"` |
| 表格 | 卡片化，表头等宽小写 |
| ` ```ts ` 等语言标记 | 代码块，顶部显示语言名 |

**目录（TOC）**：右侧目录由正文的 `##` / `###` 自动生成，滚动时高亮当前章节。至少需要 2 个标题才会显示。围栏代码块内的 `#` 会被忽略，不必担心误提取。

写作建议：每期用 3–5 个 `##` 分章（如「今日概览 / 模型与产品 / 工程实践 / 资本与人事」），目录才好用。

## 4. 自定义格式（本站专有）

以下是标准 Markdown 之外的扩展语法。**自动任务生成内容时可直接使用**。

### 4.1 提示块

GitHub Alert 语法，5 种类型：

```markdown
> [!TIP] 落地建议
> 正文支持 **Markdown**，也可以写多行。
> - 甚至可以嵌列表
```

| 类型 | 用途 | 视觉 |
| --- | --- | --- |
| `[!NOTE]` | 补充说明 | 蓝底 |
| `[!TIP]` | 建议、可操作结论 | 绿底 |
| `[!IMPORTANT]` | 重点强调 | 橙底（品牌色） |
| `[!WARNING]` | 需要注意的坑 | 黄底 |
| `[!CAUTION]` | 风险、不要做什么 | 红底 |

规则：
- `[!TYPE]` 后面同行的文字是**标题**，可留空。标题内不要写 Markdown 语法。
- 后续每行都要以 `>` 开头，空行也要写成单独一个 `>`，否则块会提前结束。

### 4.2 指标卡片 `stat`

`标签 | 数值 | 变化`（第三列可省略）。变化以 `-` 开头显示红色向下箭头，否则绿色向上。

````markdown
```stat
长上下文均价降幅 | 48% | -48%
端侧模型月活设备 | 9.1 亿 | +23%
智能体任务平均步数 | 34 |
```
````

建议 3 个或 6 个（桌面端 3 列），数值尽量简短。

### 4.3 大字引言 `quote`

正文可多行（会合并为一段）。**最后一行若以 `—` / `–` / `-` 加空格开头，视为出处。**

````markdown
```quote
我们不再关心模型能不能答对一道题，
而是关心它连续工作四十步之后还剩多少可靠性。
— MM-Agent 评测集作者访谈
```
````

### 4.4 参数对照 `kv`

`键 | 值`。适合规格、参数、配置这类信息。

````markdown
```kv
典型参数量 | 2B – 8B
首 token 延迟 | 120 – 400 ms
常见落地场景 | 摘要、改写、意图识别
```
````

### 4.5 能力对比 `compare`

**首行是表头**，其余为数据行。第一列为行标题，其余单元格支持特殊值：

| 单元格值 | 渲染 |
| --- | --- |
| `yes` / `y` / `true` | 绿色对勾 |
| `no` / `n` / `false` | 红色叉号 |
| `na` / `-` / `—` | 灰色短横（不适用） |
| 其他任意文本 | 原样显示 |

````markdown
```compare
能力 | 端侧 2B | 端侧 8B | 云端旗舰
离线可用 | yes | yes | no
长上下文（128K+） | no | no | yes
复杂多步推理 | no | na | yes
单次成本 | 近乎为零 | 近乎为零 | 按 token 计费
```
````

### 4.6 时间线 `timeline`

`时刻 | 事件 | 说明`（说明可省略）。适合事件推进、版本演进。

````markdown
```timeline
07-27 | A 厂商率先下调长上下文单价 | 128K 以上区间降价 52%
07-28 | B 厂商跟进并放开缓存额度 | 缓存命中价降至原价 10%
07-30 | 社区实测数据集中发布 |
```
````

### 4.7 导读卡片 `cards`

`标题 | 描述 | 链接`（描述、链接均可省略）。常放在正文最前面做本期导航，链接用 `#章节锚点` 可跳到本页章节。

````markdown
```cards
模型与产品 | 端侧部署量反超云端 | #模型与产品
工程实践 | 缓存友好的 prompt 结构 | #工程实践
```
````

锚点规则：**写作时直接引用中文标题即可**，例如 `## 模型与产品` 就写 `#模型与产品`，渲染时会自动换算成对应的 ASCII id。正文里的普通 Markdown 链接 `[跳转](#模型与产品)` 同样适用。

> 实现说明：页面上的真实 id 形如 `sec-1n2ik9z`（纯 ASCII）。因为中文 id 会被浏览器百分号编码，而 `#%E6%A8%A1...` 不是合法 CSS 选择器，跳转时会抛 `SyntaxError`。这一步换算对写作者透明，自动任务无需关心。

### 4.8 信息来源 `sources`

`标题 | 链接 | 备注`（备注可省略）。建议放在每期末尾。

````markdown
```sources
主流厂商定价页更新记录 | https://example.com/pricing | 官方
端侧模型部署量季度��告 | https://example.com/report
```
````

## 5. 自定义块的通用规则

适用于 `stat` / `quote` / `kv` / `compare` / `timeline` / `cards` / `sources`：

1. **分隔符是半角竖线 `|`**，前后空格会自动去掉。全角 `｜` 无效。
2. 单元格内容里**不能出现 `|`**（没有转义机制）。需要时改用「/」或「，」。
3. 空行会被忽略；第一列为空的行会被丢弃。
4. 块内文本按**纯文本**渲染，`**粗体**`、`[链接]()` 等语法不生效（唯一例外是提示块 `[!TYPE]`，其正文支持完整 Markdown）。
5. 列数不足时后面的字段按缺省处理，多出的列会被忽略。
6. 语言标记必须小写且紧贴反引号：` ```stat ` 正确，` ``` stat ` 或 ` ```Stat ` 会退化成普通代码块。
